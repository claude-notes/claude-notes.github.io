想安心摸鱼？我给 Claude Code、Codex 做了个完成提醒器

你用 Claude Code、Codex 干活的时候，有没有过这种情况：任务交出去了，想切出去做点别的，心里却还惦记着它。

隔一会儿切回来看看，还在跑。再忙点别的，等想起来，才发现它早就干完了。

想摸会儿鱼，也摸得不太踏实。

所以今年 1 月，我做了个开源提醒器，叫 AI CLI Complete Notify。

项目地址在文末

它做的事很简单：AI 干完活了，发条通知叫你回来。你可以去写点别的、回消息，不用一直守着终端。

如果你看过第一篇介绍，可能还记得那个挺长的标题：《AI完成任务太耗时？想要摸鱼却又怕耽误时间，于是我做了个AI任务完成提醒器》。当时想解决的，就是这点小麻烦。

几个月过去，它还在更新。有人来报问题，有人问能不能加个功能，也有朋友直接提交代码，把自己需要的东西补了进来。

今天再跟你聊聊这个小工具。之前用过的，可以看看多了什么；第一次见到它的，也能顺便了解一下，适不适合自己的用法。

有人在认真用，也有人一起补功能

截至写稿时间，这个 GitHub 仓库 已经有 400+ 个 Star、30 个 Fork。

翻翻 Issue 和 PR，会更容易看出大家怎么用它。

比如，有朋友问：Codex 和 Claude 能不能分别发到不同的 Webhook 地址？现在已经可以了，你可以把两个工具的通知分开，不用全挤进同一个群。

还有朋友直接动了手。WALKERKILLER 补了飞书卡片；8liang 加了 Gotify 通知、macOS 隐藏 Dock 图标和 Herdr 集成；Windyskr 改进了 Watch 与 Hooks 的混合运行；Atoony 带来了 ZCode 接入。这些 PR 都已经合并了。

一开始是我自己需要一个提醒，后来大家也把各自的用法带了进来。如果你已经在用，其中有些功能，就是这些朋友补上的。

有好评，也有具体的问题

9 月，Higurashi-kagome 在 GitHub 留了这么一段话：

使用挺长时间了，一直是手动更新，在体验过的通知软件中感受最好，感谢开发。👍

这段话在Issue #39里，这段话确实给了我很大的动力。不过，点进去你会发现，这位朋友是来反馈“检查更新失败”的。

所以好评得收下，检查更新的问题也得接着处理。既然是帮你省心的小工具，更新的时候也该少让你操心。

其他类似的问题就比如：有人碰到过重复提醒、漏提醒，或者企业微信收不到消息。你大概能理解这种别扭：没通知，还是得自己回去看；通知太多，又想把它关掉。

后面不少改动，都是在处理这些事，已经尽可能减少上面这些问题的发生了。

现在可以接哪些 AI 工具

如果你用的是 Claude Code、Codex、Gemini CLI、OpenCode 或 ZCode，现在都可以接进来。另外，用 Herdr 管理 AI 任务的朋友，也可以接它的社区通知插件。

前面这五个 AI 来源可以分别开关，也能各自设置耗时阈值和通知渠道。

比如，你想让 Claude 的长任务发到飞书，Codex 发到 Telegram，就可以分开设置。几秒钟就结束的任务，可以不用提醒；任务结束时，耗时超过你设定的时间，再叫你。来源专属的 Webhook 地址目前要填在配置文件里，界面还没有对应的地址输入框。

接入方式跟第一篇比，也有些变化。

之前主要靠监听日志。现在，Claude Code、Gemini CLI 和 ZCode 可以用原生 Hook：工具结束任务时，直接发出一个事件。OpenCode 通过全局插件接收事件。Codex 在这个项目里，仍然主要靠 Watch 监听日志。

你可以让这两种方式一起工作，Claude 走 Hook，Codex 继续监听日志。同一次完成如果两边都捕获到了，会做去重处理。

这里有个使用时会感觉到的区别：Hook 能更接近任务真正结束的时刻；Watch 得等日志安静下来。默认有工具调用时等 60 秒，没有工具调用时等 15 秒。你用 Watch 时，提醒可能会晚一点，别把这段等待当成没反应。

通知可以发到你平时看的地方

你平时习惯看哪个应用，就把提醒放到那里。

现在支持飞书、钉钉、企业微信等 Webhook，也支持 Telegram Bot、邮件、桌面通知、声音或语音播报、Gotify。如果你已经有自己搭的 Gotify 推送服务，也能接上。

不用把渠道全打开。你一直在电脑前，桌面通知或者一声提示音就够了；想离开电脑，就配一个手机上常看的应用。当然，同时开几个渠道也可以。

通知也能到手腕上。我就喜欢连接飞书，之后在手环上开启飞书提醒就可以啦，特别是当你有多台设备的时候。

需要手表、手环接收提醒的话，需要看一下手机和设备的通知设置是否打开。 工具目前还没有专门的手表原生通道，主要是想想没这必要，也不想给大家增加学习成本。

通知里还能带上任务输出，飞书可以用卡片展示。如果你觉得输出太长，也可以打开 AI 摘要，让它先整理成一段简短说明。

摘要需要自己配模型 API，调用会经过你配置的服务。不想配也没关系，普通提醒照样能用；摘要超时了会回退，不会一直卡着等它。

平时少打扰，需要你时再出现

还有一种情况：AI 没干完，等着你做选择。

现在有一个可选的 Codex 确认提醒。在 Watch 模式下，遇到需要选择或提交的 Plan 交互选项，它可以通知你。这个选项默认关闭，也不是所有权限审批都能提醒，想用的话再打开。

桌面端可以开机自启，启动后藏到托盘里。macOS 也能隐藏 Dock 图标，只留菜单栏入口。点击通知切回编辑器或终端也有支持，不过能不能顺利切回去，还会受系统焦点规则影响。

配好以后，就让它在后台待着。

现在怎么用

截至写稿时，公开下载的最新版本是 v2.17.0。主分支的版本号已经写到了 2.18.0，你下载时看 Releases 页面就好。

Windows 有 x64 便携 ZIP，解压就能运行。Mac 现在可以直接下 DMG，M 系列芯片和 Intel 各有一个安装包，不用为了装它再准备 Node.js 或 Rust 环境。

Mac 需要 macOS 13.5 或更新版本。安装包还没通过 Apple 公证，第一次打开可能遇到系统验证提示。Linux 用户，或者想从源码运行的朋友，可以照着 README 配置；源码桌面开发需要 Node.js/npm 和 Rust/Cargo。

第一次用，别急着把所有东西都配一遍。先选一个 AI 工具、一个通知渠道，发一条测试通知，再让 AI 真正做一轮任务，看看结束后能不能收到提醒。

测试按钮能发出消息，只说明通知渠道通了，真实任务还要跑一次。如果你用 ZCode，装好或更新 Hook 后，记得完全退出、重新打开，再新建一个会话。

你要是也经常一边等 AI，一边切出去写东西、回消息，或者想安心摸会儿鱼，可以试试。

还是第一篇里那个意思：AI 干完活了，叫你一声。
